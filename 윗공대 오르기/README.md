# 오르막! — 윗공대까지 1,500m

SNU-vibe-coding / Team-2

2D 도트 스타일 자동 달리기 게임입니다. **`index.html`을 Chrome 또는 Edge에서 열면 바로 플레이할 수 있습니다.** 설치나 빌드가 필요하지 않습니다. 그래픽과 코드는 HTML에 들어 있으며 BGM은 `assets/bgm.wav`에 있습니다. 파일을 공유하거나 이동할 때 `assets` 폴더도 함께 옮겨주세요.

제공된 BeepBox BGM은 **3·2·1 카운트가 끝난 뒤** 반복 재생됩니다. 게임 오버·완주·나가기·연결 종료 시 정지하고, 새 판은 카운트 종료 후 처음부터 재생합니다. 점프·버스 회피·자동차 회피에는 서로 다른 짧은 8비트 효과음이 재생됩니다. 온라인에서는 자신이 실제로 수행한 조작만 소리가 납니다. 솔로에서 설정을 열거나 다른 탭으로 이동하면 음악도 일시정지합니다. 브라우저가 온라인 자동 시작 시 음악을 차단하면 첫 조작 입력에서 재생을 다시 시도합니다.

## 플레이

화면 전체가 게임 영역입니다. 내 거리와 상대 거리는 게임 화면 상단, 정류장 경로는 하단에 표시합니다. 우측 상단에는 `남은 시간 / 개인 최고기록`이 표시됩니다. 규칙은 시작 메뉴의 **게임 플레이 방법 보기**에서 확인할 수 있습니다.

시작 메뉴는 **윗공대 오르기** 제목으로 표시되며, 출발 전 화면 중앙에 큰 숫자로 3·2·1을 셉니다. 우측 상단 **설정**에서 플레이 중 조작 도움말을 켜거나 끌 수 있고 선택은 브라우저에 저장됩니다. 출발 카운트, 충돌·버스 탑승 알림과 터치 조작 버튼은 유지됩니다.

- 솔로: 메인화면에서 **쉬움·보통·어려움·매우 어려움**을 고르고 **혼자 달리기**를 누르세요. 최고 기록은 난이도별로 저장됩니다. 기존 최고 기록은 보통 난이도에서 유지됩니다.
- 자동 이동: 초속 12m, 제한시간 3분 01초, 목표 1,500m.
- `Space` / `↑`: 점프. 돌과 고깔에 걸리면 1초간 멈춥니다.
- `→`: 0.7초간 버스 회피, 쿨타임 없이 즉시 재사용. 시간이 끝나거나 자동차 회피를 입력하면 버스 회피와 안전 판정이 종료됩니다.
- `←`: 0.7초간 자동차 회피. 쿨타임 없이 재사용합니다. 점프나 `→`로는 자동차를 피할 수 없습니다. 부딪히면 공중으로 튕겨 올라가 약 1.15초 후 충돌 위치보다 30m 뒤에 착지합니다. 출발점 이전으로는 가지 않습니다. 비행 중 추가 충돌을 받지 않으며 착지 후 자동차에 대해서만 1초간 보호됩니다.
- 모바일: 화면 아래 점프·회피 버튼을 사용합니다.
- 자동차·버스 충돌은 왼쪽 맨 앞부분의 좁은 구간에서만 판정합니다. 앞부분이 지나간 뒤에는 차체 옆이나 뒤가 겹쳐도 충돌하지 않습니다. 빠르게 지나가도 앞부분이 통과한 경로를 검사해 충돌 누락을 방지합니다.
- 솔로는 다른 탭으로 이동하면 일시정지합니다. 온라인은 계속 진행됩니다.

5513·5516번 초록 버스가 번갈아 초속 14m로 내리막 방향으로 이동합니다. 부딪히면 버스를 타고 가장 가까운 **이전** 정류장으로 돌아갑니다. 탑승 중에도 시간이 흐르며, 하차 후 버스에 대해서만 2.5초간 보호됩니다.

자동차는 흰색·검은색·빨간색·파란색의 세단과 SUV로 등장합니다. 버스와 같은 초속 14m로 내려오며 차량의 간격을 유지합니다. 버스·자동차 충돌 구간 사이의 최소 대응 여유는 보통·어려움 0.5초, 쉬움 0.8초입니다. 두 플레이어가 떨어져 있거나 정류장으로 되돌아가도 차량끼리 간격을 유지합니다. 회피 방향을 전환하면 이전 종류 차량의 안전 판정은 즉시 종료됩니다.

자동차 회피도 0.7초간 유지되며, 버스 회피를 입력하면 즉시 종료됩니다. 자동차 뒤쪽으로 그리는 효과도 회피 종료 시 끝납니다. 돌·고깔에 걸려 멈춘 중에도 자동차·버스 회피를 사용할 수 있습니다. 무적은 돌·고깔, 자동차, 버스별로 따로 적용됩니다. 자동차 착지 후에는 자동차만 1초, 버스 하차 후에는 버스만 2.5초 보호됩니다.

매판 장애물 위치·종류와 차량 등장 시점을 난수로 정합니다. 진행 거리에 따라 장애물 평균 간격이 감소하며 차량 배차도 최대 12% 짧아집니다. 안전 간격과 버스 배차를 우선하므로 실제 차량 등장은 지연될 수 있습니다.

매우 어려움의 버스·자동차 대응 여유는 0.25초입니다. 하단에는 안내 제목 없이 노선도만 표시하며, 파란 원은 자신의 실시간 위치, 빨간 원은 온라인 상대의 위치를 나타냅니다. 정류장 간 거리를 보간해 각 정류장 도착 시 해당 지점에 원이 놓입니다. 같은 위치에 있으면 두 원을 위아래로 조금 나눠 표시합니다.

완주는 **완주!**와 `02:39.73` 형식의 기록만, 실패는 **게임 오버!**만 표시합니다. 두 결과 화면 모두 **솔로 다시플레이 / 메인화면으로** 버튼을 제공합니다. 재플레이는 같은 난이도의 새로운 코스로 시작합니다.

## 온라인 2인 대결

1. 두 사람이 배포된 사이트에서 **친구와 대결**을 선택합니다.
2. 한 사람이 **방 만들기**를 누르면 방에 입장해 대기하며 6자리 방번호가 표시됩니다.
3. 친구는 **방 들어가기**를 눌러 번호를 입력합니다.
4. 연결되면 자동으로 3·2·1 카운트 후 출발합니다. 방장의 난이도가 적용됩니다.

방번호는 5분간 유효하고 최대 2명만 입장할 수 있습니다. 대기 창을 닫으면 방을 취소합니다. 방번호는 연결 정보를 교환할 때만 사용하고 경기 중에는 WebRTC로 직접 통신합니다. 로컬 HTML 파일은 솔로만 지원합니다.

### Vercel 배포 설정

- GitHub 저장소를 Vercel 프로젝트에 연결하고 **Root Directory를 `윗공대 오르기`**로 지정합니다. (이 폴더 내용만 저장소 루트에 올린 경우 `.`)
- Framework Preset: **Other**, 별도 Build Command 없음, Output Directory: `.`.
- Vercel Marketplace에서 Upstash Redis를 연결합니다. 서버 환경변수 `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`을 설정합니다. 통합에서 제공하는 `KV_REST_API_URL`, `KV_REST_API_TOKEN` 이름도 지원합니다. 읽기 전용 토큰은 사용할 수 없습니다.
- 환경변수 추가 후 재배포합니다. 토큰은 HTML이나 Git에 넣지 않습니다. `.env.example`은 변수 이름만 보여주는 예시입니다.
- `api/rooms.py`가 Vercel Python Function으로 실행됩니다. 별도 Python 패키지가 필요하지 않습니다. Redis는 여러 함수 인스턴스가 같은 방을 찾도록 합니다.
- 방 생성 충돌 재시도, 원자적 1명 입장 제한, 인증 토큰, 5분 만료, 요청 빈도 제한을 적용합니다. 생성/입장은 IP당 분당 60회, 상태 확인은 600회입니다.

공식 문서: [Vercel Python Functions](https://vercel.com/docs/functions/runtimes/python), [Upstash REST API](https://upstash.com/docs/redis/features/restapi).

온라인에서는 초대한 사람이 선택한 난이도를 적용하며 난수 시드와 장애물 배치를 공유합니다. 두 사람 모두 동일한 코스로 대결합니다.

WebRTC 데이터 채널로 연결하며, 초대한 브라우저가 이동·충돌·타이머·승패를 계산해 동기화합니다. 각자 자신은 파랑, 상대는 빨강으로 보며 카메라는 자신을 중앙에 두고 뒤 30m부터 앞 30m까지 총 60m를 보여줍니다. 캐릭터가 겹치면 자기 캐릭터를 마지막에 그립니다. 상대가 화면 밖에 있어도 상단 거리로 진행 상황을 확인할 수 있습니다.

인터넷 연결과 WebRTC 지원 브라우저가 필요합니다. Google의 공개 STUN 서버를 사용하며 중계용 TURN 서버는 포함하지 않습니다. 따라서 일부 학교·회사망이나 제한적인 NAT 환경에서는 연결되지 않을 수 있습니다. 다른 네트워크 또는 핫스팟에서 재시도하세요. 자동 매칭·경기 중 재접속 기능은 없습니다. 초대자가 탭을 오래 숨기면 브라우저 제한으로 동기화가 지연될 수 있으므로 플레이 중에는 게임 화면을 열어두세요. 파일 이동 또는 브라우저 저장소 삭제 시 솔로 기록이 유지되지 않을 수 있습니다.

## 차량 효과음

자동차 충돌 시 낮아지는 8비트 충격음이 한 번 재생됩니다. 버스에 탑승해 이전 정류장으로 돌아가는 동안 낮은 엔진음이 이어지고, 도착 약 1.1초 전(짧은 이동은 탑승 직후) 라♭(A♭5) → 파(F5) 하차 벨이 각 0.3초씩 한 번 울립니다. 자신의 차량 이벤트만 재생하며, 하차·일시정지·종료 시 엔진음이 멈춥니다.

서울 시내버스의 [하차벨 음질 개선 안내](https://mediahub.seoul.go.kr/archives/171366)와 [에어로시티 하차벨 음형 설명](https://readonly.wiki/w/현대%20슈퍼%20에어로시티)을 참고한 합성 효과음입니다. 원본 녹음을 재생하거나 특정 차종 소리를 정확히 복제한 것은 아닙니다.

서울 지선버스의 초록 차체·짙은 창문 띠·배색은 [서울 버스 사진](https://www.khan.co.kr/article/201706191744001)을 참고했습니다. 사진은 게임에 포함하지 않았으며, Canvas로 문이 없는 측면 도트 그래픽을 직접 그립니다.

## 검증

Python과 Chrome 또는 Edge가 있으면 `python tests/check_browser.py`로 실제 브라우저에서 이동, 장애물, 버스 회피·복귀, 정류장 경계, 제한시간, 승패, 시점 로직을 검사합니다. `python tests/check_online.py`는 두 게임 문서 사이에 실제 WebRTC 연결을 만들고 출발, 상대 입력, 상태 동기화, 승패 및 연결 종료를 검사합니다. 다른 경로의 브라우저는 `CHROME_PATH` 환경변수로 지정할 수 있습니다. 캡처는 Git에서 제외된 `.qa/`에 생성됩니다. 온라인 검증은 로컬 연결 기준으로, 서로 다른 네트워크의 실사용자 간 연결은 별도 확인이 필요합니다.

BGM 반복은 Web Audio 버퍼 루프를 사용합니다. 원본 WAV는 보관하고 끝·시작 5ms를 겹쳐 연결한 데이터를 `assets/bgm-loop.js`에 포함했습니다. `assets/audio-player.js`가 이 데이터를 디코딩해 재시작 지연 없이 반복합니다. HTML을 직접 열 때도 동작하도록 네트워크 요청 없이 데이터를 로드합니다.

### 방번호 기능 테스트

프로젝트 폴더에서 `python -m pip install --target .qa/testdeps "fakeredis[lua]"` 후 `python tests/check_rooms.py`, `python tests/check_online.py`를 실행합니다. 실제 Lua 방 로직을 로컬 Redis 에뮬레이터에서 검사하고, 두 Chrome 문서를 6자리 번호로 연결해 실제 WebRTC 경기를 검증합니다. 배포된 Upstash 및 외부 NAT 통과 여부는 별도 실제 기기 확인이 필요합니다. 기존 게임 회귀 테스트는 `python tests/check_browser.py`입니다.
